# 노목돈(NomokDon) — 기획서 v3.1

> **"목돈이 필요 없다"**  
> 재한 외국인을 위한 XRPL 기반 **주거 신뢰 패스**
>
> 외국인이 한국에서 집을 구할 때 필요한 신원, 비자, 월세 납부 신뢰, 예약금 보호 상태를  
> XRPL Credential과 Escrow로 증명하는 주거 신뢰 인프라입니다.

---

## 1. 문제 정의

### 재한 외국인의 주거 금융 현실

한국에 거주하는 외국인은 약 250만 명을 넘어섰지만, 한국 특유의 전세·보증금 제도 앞에서 구조적으로 불리한 위치에 놓여 있습니다.

| 문제 | 현황 |
|------|------|
| **보증금 진입장벽** | 서울 원룸 평균 보증금 1,000~3,000만원. E-9 근로자 평균 월급 250만원 기준 4~12개월 치 급여에 해당 |
| **금융 접근성 제한** | 전세자금대출·보증보험이 일부 은행(KB, 하나 등)에서 제한적으로 가능하나, **접근성이 현저히 낮고 정보 비대칭이 심함**. 대부분의 외국인이 이러한 상품의 존재 자체를 모름 |
| **신용 데이터 부재** | 한국 금융 이력이 없어 신용 심사 자체가 불가. 성실하게 월세를 납부해도 신용으로 인정 안 됨 |
| **보증금 반환 리스크** | 계약 종료 후 임대인이 반환을 미루거나 거부하는 사례 빈번. 외국인은 법적 대응력 부족 |

> **핵심 인사이트**: "보증금"은 재한 외국인 금융 문제 중 **체감 강도 1위**이며, 25개 경쟁 프로젝트 중 이 영역을 다루는 팀은 **0팀**입니다.

### 임대인이 보증금을 요구하는 이유

보증금은 임차인 입장에서는 진입장벽이지만, **임대인 입장에서는 리스크 담보**입니다. "보증금 0원"을 말하려면, 임대인에게 "그럼 내 리스크는 누가 책임지나?"에 먼저 답해야 합니다.

| 임대인의 불안 | 보증금이 해결해주는 것 | 노목돈의 대안 |
|-------------|---------------------|-------------|
| 월세 연체/미납 | 보증금에서 차감 | 월세 납부 이력 + 보증 파트너 연계 |
| 원상복구 비용 | 보증금에서 공제 | 예약금 Escrow (조건부 잠금) |
| 임차인 신원 불확실 | 목돈을 낼 수 있다 = 최소한의 신뢰 | DID + 비자 Credential + Risk Score |
| 야반도주/비자 만료 | 보증금으로 손실 보전 | Credential 만료 트리거 + 보증보험 |

> Web2 시장에서는 이미 개런티즈 같은 무보증금 월세보증 모델이 "보증금 문제는 실제 수요가 있는 문제"임을 보여주고 있습니다. 하지만 기존 모델은 국내 신용정보와 Web2 보증 운영에 의존하기 때문에 한국 금융 이력이 부족한 외국인에게는 접근성이 제한됩니다. 노목돈은 외국인의 비자·체류·월세 납부 이력을 DID/Credential과 XRPL Escrow로 연결해, 외국인도 임대인에게 신뢰를 증명하고 목돈 없이 입주할 수 있는 주거 금융 인프라를 만듭니다.

### 타겟 시장

| 세그먼트 | 규모 | 심각도 |
|---------|------|:---:|
| 비전문취업(E-9) | ~25만명 | 🔴 |
| 유학생(D-2/D-4) | ~15만명 | 🔴 |
| 재외동포(F-4/H-2) | ~70만명 | 🟡 |
| **직접 타겟** | **~80~120만명** | — |

## 2. 솔루션: 주거 신뢰 패스 + 예약금 Escrow 보호

### 사용자 플로우 (5단계)

| 단계 | 외국인 임차인이 하는 일 | 뒤에서 일어나는 일 |
|:---:|----------------------|------------------|
| **1** | 토스/노목돈에서 DID + 비자 Credential 생성 | XRPL DIDSet + Credential 발급 |
| **2** | 보증금 낮은 매물 선택 | 제휴 중개사 매물 풀에서 매칭 |
| **3** | 월세 신뢰 리포트 생성 → 임대인 공유 | AI Risk Score + Credential 기반 리포트 자동 생성 |
| **4** | 예약금 납부 (Escrow 보호) | XRPL Escrow에 조건부 잠금 |
| **5** | 매월 월세 납부 → 주거 신용 프로필 축적 | 납부 이력 온체인 해시 기록 → 신용 데이터 축적 |

> 기술 다이어그램은 뒤에 두고, 앞에는 "집 구하기 플로우"로 보여줍니다.

### 이해관계자별 가치 제안

| | 외국인 임차인 | 임대인 | 중개사 / 토스 / 파트너 |
|---|---|---|---|
| **핵심 메시지** | 목돈 없이 입주 | 외국인 리스크 사전 제거 | 외국인 고객 계약 전환율 증가 |
| **가치 1** | 보증금 마련 고민 해소 | DID/Credential로 임차인 신원 사전 확인 | 돌아가던 외국인 고객을 계약으로 전환 |
| **가치 2** | 비자 기반 신뢰 증명으로 집 구하기 | Escrow/보증 구조로 월세·퇴거 리스크 완화 | 검증된 외국인 임차인 풀 확보 |
| **가치 3** | 월세 이력 = 한국 금융 신용 축적 | 공실 해소 (외국인 시장 접근) | 금융 데이터 독점 (토스뱅크 연계) |
| **가치 4** | 고금리 전세대출 불필요 | 임대관리 부담 감소 (플랫폼 운영) | 수수료 수익 + Recurring Revenue |

### Phase 0 핵심 구조 (해커톤 데모 범위)

```
[외국인 임차인]                                       [제휴 중개사/임대인]
     │                                                │
     ├─ ① DID + Credential 발급                        │
     │   (비자+고용 온체인 증명)                          │
     │                                                │
     ├─ ② 월세 신뢰 리포트 생성 → 임대인 공유             │
     │   (AI Risk Score + Credential 기반)              │
     │                                                │
     │       ┌────────────────────┐                     │
     │       │ XRPL Escrow        │                     │
     │       │ (예약금 조건부 예치) │─── ③ 계약 체결 ────→│
     │       │ (XRP 기반 PoC)     │                     │
     │       └────────────────────┘                     │
     │                                                │
     ├─ ④ 월세 납부 (RLUSD Payment)                     │
     │   → 납부 이력 온체인 해시 기록                      │
     │                                                │
     ├─ ⑤ 계약 종료                                     │
     │   (다중서명: 중개사+플랫폼)                         │
     │                                                │
     │       ┌────────────────────┐                     │
     │       │ Escrow 해제 → 반환  │─── ⑥ 예약금 반환 ──→│
     │       └────────────────────┘                     │
     │                                                │
     └─ 월세 납부 이력 축적 ──→ 외국인 주거 신용 프로필 ──→ 금융 접근 확대
```

### Phase 2 확장 구조 (Vault 기반 보증금 유동화)

> Phase 0에서 신뢰 인프라가 검증된 후, 금융위 샌드박스 승인을 거쳐 Vault 모델을 도입합니다.

```
[외국인 임차인]          [Vault 예치자]           [제휴 임대인/중개사]
     │                   │                       │
     │                   ├─ Vault에 자금 예치       │
     │                   │  (DepositPreauth로      │
     │                   │   KYC 인증자만 참여)     │
     │                   │                       │
     │    ┌──────────┐   │                       │
     │    │ Escrow   │←──┘ Vault 자금으로         │
     │    │ 보증금   │     보증금 대납 ────────→   │
     │    └──────────┘                           │
     │                                          │
     ├─ 월세 + Vault 수수료 납부 ──→ (예치 수익)    │
     │                                          │
     └─ 계약 종료 → Escrow 반환 → Vault            │
```

### Phase 0 트레이드오프: 보증금 부담 경감

| 비교 | 기존 (보증금 직접 납부) | 노목돈 Phase 0 | 노목돈 Phase 2 (Vault) |
|------|---------------------|---------------|----------------------|
| **초기 비용** | 2,000만원 일시 납부 | 예약금 100~300만원 + 신뢰 리포트 | **0원** (Vault 대납) |
| **월 추가 비용** | 0원 | 월세만 납부 | ~12만원 (Vault 수수료) |
| **보증금 반환 리스크** | 있음 (법적 소송 필요) | 예약금 Escrow로 보호 | 전액 Escrow 보호 |
| **임대인 설득** | 기존 방식 | 신뢰 리포트 + 예약금 보호 | 보증금 전액 확보 |

> Phase 0은 보증금을 "없애는" 것이 아니라, **신뢰 리포트로 보증금을 낮추고 예약금을 Escrow로 보호**하는 모델입니다. Phase 2에서 Vault 도입 후 보증금 전액 대납이 가능해집니다.

## 3. XRPL 기술 활용

### 왜 XRPL인가?

> **"예약금 조건부 예치 = XRPL Escrow"**  
> DB도 기록은 가능하지만, XRPL Escrow는 **제3자가 독립적으로 검증 가능한 예약금 잠금 상태**를 제공합니다. 운영자도 조건 충족 전에는 자금을 이동할 수 없으며, 개인정보(여권 번호 등)는 오프체인에 암호화 저장하고 온체인에는 해시만 기록해 프라이버시를 보호합니다.

| 비교 | XRPL | 중앙화 DB |
|------|------|----------|
| 예치금 변조 | **불가능** (프로토콜 강제) | 운영자가 변경 가능 |
| 신뢰 구조 | 코드가 보장 | 운영 회사 신뢰 필요 |
| 외국인 입장 | 한국 회사 신뢰 불필요 | 중소 중개업소를 신뢰해야 함 |
| 개인정보 보호 | 해시만 온체인, 원본 암호화 | 운영사 DB에 원본 저장 |

> **CredBundle과의 핵심 차이**: CredBundle의 Credential은 DB로도 일부 구현 가능하지만, 노목돈의 Escrow는 **제3자가 검증 가능한 자금 잠금 상태**라는 점에서 DB와 근본적으로 다릅니다.

### XRPL 기능 매핑 (4가지 핵심 + 1가지 확장)

| XRPL 기능 | 용도 | 기술적 근거 |
|-----------|------|------------|
| **Escrow** | 예약금/Vault 자금 조건부 예치 & 반환 | `Crypto-Condition`으로 계약 종료 조건 설정. **다중서명(공인중개사+플랫폼)**이 오프체인 확인 후 해제 |
| **Credential (XLS-70)** | 비자·체류자격 온체인 증명 | 비자 유형 + 만료일 → Credential 발급. Expiration 연동으로 **만료 시 갱신 알림 및 리스크 플래그** 발생 |
| **DIDSet** | 외국인 신원 관리 | 여권 해시 → 온체인 DID. 개인정보는 오프체인, 증명만 온체인 |
| **DepositPreauth** | Vault 참여자 접근 제어 | KYC 완료된 예치자만 참여 허용. 무인가 참여 차단 |
| *(확장)* **Cross-Currency Payment** | 보증금 반환 → 본국 송금 | Phase 1+에서 토스 해외송금 연동 시 활용 |

### 기술적 한계 — 솔직한 인정

| 한계 | 현재 상태 | 대응 |
|------|---------|------|
| **TokenEscrow 미활성화** | XLS-85가 `Open for Voting` 상태. RLUSD를 직접 Escrow에 넣을 수 없음 | 해커톤 데모: **XRP 기반 Escrow로 PoC**. TokenEscrow 활성화 시 RLUSD 전환 로드맵 제시 |
| **Hooks 미배포** | `In Development` 상태 | 기획서에서 Hook 언급 제거. 자동화는 오프체인 트리거 + 다중서명으로 해결 |
| **오라클 문제** | 명도 확인을 온체인으로 직접 증명 불가 | **공인중개사 + 플랫폼 다중서명** 구조로 해결 (오라클 = 신뢰할 수 있는 사람) |

> **이 한계들을 심사위원이 지적하기 전에 먼저 말하는 것**이 핵심 전략입니다. "우리도 이 한계를 알고, 이렇게 설계했습니다"가 "몰랐네요"보다 100배 강합니다.

## 4. 신뢰 스택 (Trust Stack)

> 보증금은 임대인이 불안을 선불로 받은 돈입니다. 노목돈은 그 불안을 5계층 신뢰 스택으로 대체합니다.

| 계층 | 구성 요소 | XRPL 연결 | 역할 |
|:---:|-----------|-----------|------|
| **L1** | **DID / Credential** | DIDSet + Credential (XLS-70) | 여권 해시, 비자 유형, 체류 만료일, 고용/재학 상태 온체인 증명 |
| **L2** | **신뢰 체크리스트** | 오프체인 검증 → 온체인 해시 앵커링 | 비자 유효, 고용/재학 확인, 월세 부담률, 예약금 잠금 상태 — 설명 가능한 항목별 배지 |
| **L3** | **XRPL Escrow** | Escrow + Crypto-Condition + MultiSign | 예약금/보증성 자금을 계약 조건 충족 전까지 임의 이동 불가하게 잠금 |
| **L4** | **Partner Guarantee** | DepositPreauth (참여자 제어) | 보증보험사, 중개사, 고용주, 지자체 파일럿 자금과 연계 |
| **L5** | **Recovery Process** | Credential Expiration → 갱신 알림/리스크 플래그 | 연체 알림 → 예약금 정산 협의 → 파트너 보상 → 신용 프로필 반영 |

```
임대인이 보는 신뢰 흐름:

"이 외국인을 받아도 되는 이유"
     │
     ├─ L1: 비자 E-9, 체류 만료 2027-06, 고용보험 가입 확인 ✅
     ├─ L2: 신뢰 배지 — 비자 유효 ✅ 고용 확인 ✅ 월세 부담률 24% ✅ |
     ├─ L3: 예약금 200만원 XRPL Escrow 잠금 완료 ✅
     ├─ L4: 제휴 중개사 검증 매물 + 향후 보증 파트너 연계 ✅
     └─ L5: 연체 시 알림 → 예약금 정산 협의 → 신용 프로필 반영 ✅
```

## 5. 신뢰 리포트 — 외국인 월세 신뢰 리포트

블록체인을 먼저 보여주는 것이 아니라, **임대인이 실제로 보는 리포트**를 보여준 뒤 그 근거가 DID/Credential/Escrow라고 설명하면 설득력이 커집니다.

### 리포트 구성: 설명 가능한 신뢰 배지

> 블랙박스 점수가 아니라, **임대인이 항목별로 확인할 수 있는 배지** 형식입니다.

| 신뢰 배지 | 데이터 출처 | 표시 예시 |
|-----------|-----------|----------|
| **비자 유효** | XRPL Credential (XLS-70) | ✅ E-9, 만료 2027-06 |
| **고용/재학 확인** | 고용보험 API + Credential | ✅ 고용보험 가입 확인 |

## 10. 경쟁 포지셔닝

### vs CredBundle (최대 경쟁자)

| 비교 | 노목돈 | CredBundle |
|------|--------|-----------|
| **"왜 블록체인?"** | **Escrow = 제3자 검증 가능한 잠금 상태** 🟢 | Credential = DB로 가능? 🟡 |
| **감정적 호소력** | "목돈 없이 집 구하기" = 1초 이해 🟢 | "대출 심사 통과" = 기술적 🟡 |
| **경쟁 공백** | 주거 금융 = **0팀** 🟢 | Credential = 3팀 경쟁 🔴 |
| **실현 가능성** | Phase 0 데모 가능 🟢 (Vault는 Phase 2) | 정부 API 연동 = 간단 🟢 |
| **규제 리스크** | Phase 0은 금융상품 아님 🟢 | 정보 연동 = 낮음 🟢 |

> **노목돈의 승부처**: "왜 블록체인?" + 감정적 호소력 + 블루오션. 이 세 가지에서 CredBundle을 압도.
> **CredBundle의 약점 공략**: "Credential은 DB로도 되지 않나요?" → 심사위원이 이 질문을 하면 CredBundle이 흔들림.

## 14. 예상 심사 Q&A

| 질문 | 답변 |
|------|------|
| **"DB로도 되지 않나?"** | DB도 기록은 가능합니다. 하지만 XRPL Escrow는 **제3자가 독립적으로 검증 가능한 예약금 잠금 상태**를 제공합니다. 외국인이 한국 중소 중개업소의 DB를 신뢰할 수 있을까요? 이것이 DB와의 결정적 차이입니다. |
| **"RLUSD를 Escrow에 넣을 수 있나?"** | 솔직히, 현재 **TokenEscrow(XLS-85)가 Open for Voting 상태**라 직접 불가합니다. 해커톤 데모는 XRP 기반 Escrow로 PoC를 보여드리고, TokenEscrow 활성화 시 RLUSD로 전환합니다. |
| **"임대인이 왜 이걸 받아들이나?"** | Phase 0은 보증금을 없애는 게 아닙니다. **신뢰 리포트**로 외국인 임차인의 신원·비자·고용 상태를 사전 확인하고, 예약금은 Escrow로 보호합니다. 임대인은 블록체인을 몰라도 리포트를 보고 판단할 수 있습니다. |
| **"외국인이 월세를 안 내면?"** | 예약금 Escrow에서 정산 + 신용 프로필에 반영됩니다. Phase 2에서 Vault 도입 시 보증보험 연계로 디폴트 리스크를 추가 헤지합니다. |
| **"금융상품 아닌가? 규제는?"** | Phase 0은 투자자 모집·수익 약속·자금 풀링을 제외하도록 설계했습니다. Vault는 Phase 2에서 금융위 샌드박스 승인 후 도입합니다. |
| **"명도 확인은 어떻게?"** | 공인중개사 + 플랫폼의 **다중서명** 구조입니다. 완전한 온체인 자동화가 아닌, 신뢰할 수 있는 기관이 오프체인에서 확인 후 온체인 해제를 트리거합니다. |
| **"비자 만료 후 도주하면?"** | Credential 만료 시 **갱신 알림과 리스크 플래그**가 발생합니다. 정산 여부는 계약 조건에 따라 협의하며, 향후 보증보험 연계로 디폴트 리스크를 헤지합니다. |
| **"개런티즈 같은 Web2 서비스와 뭐가 다르나?"** | 개런티즈는 국내 신용정보 기반 Web2 보증 모델입니다. 한국 금융 이력이 없는 외국인은 이용 자체가 어렵습니다. 노목돈은 비자·체류·고용 데이터를 DID/Credential로, 자금 보호를 XRPL Escrow로 해결해 **외국인도 신뢰를 증명**할 수 있습니다. |
| **"누가 Credential 발급자인가?"** | Phase 0에서는 노목돈 플랫폼이 고용보험 API 데이터를 검증한 후 Credential을 발급합니다. 향후 출입국관리사무소나 인증 기관이 직접 발급하는 구조로 확장 가능합니다. |
| **"임대인이 신뢰 리포트만으로 보증금을 낮춤까?"** | Phase 0은 제휴 중개사의 저보증금 매물과 연결합니다. 임대인이 리포트만 보고 판단하는 게 아니라, 중개사가 검증한 매물 풀 안에서 매칭됩니다. |
| **"금융상품 아닌 근거는?"** | Phase 0은 투자자 모집·수익 약속·자금 풀링을 제외하도록 설계했습니다. Vault는 Phase 2에서 금융위 샌드박스 승인을 받은 후 도입합니다. |

> 예약금 = Escrow. 제3자가 검증 가능한 잠금 상태는 DB로 대체하기 어렵습니다.
