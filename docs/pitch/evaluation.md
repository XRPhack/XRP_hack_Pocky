# 🔍 노목돈(NomokDon) — 냉정한 경쟁력 평가

> **평가 기준**: 토스 특별상 심사 기준 5가지 (각 10점, 총 50점)
> **비교 대상**: KFIP 2026 등록 20개 프로젝트

---

## 최종 스코어: 38/50 (4위)

## 항목별 채점 근거

### ① 문제 정의 명확성: 9/10 ✅ 강점

**좋은 점:**
- "보증금"은 재한 외국인의 **체감 1순위 pain point**. CredBundle의 "대출 심사"보다 감정적 호소력 강함
- 250만 외국인 시장 규모 명확
- "목돈이 필요없다"는 네이밍이 문제를 1초만에 설명

**감점 이유 (-1):**
- 모든 외국인이 보증금 문제를 겪진 않음 (주재원, 기숙사 거주 유학생 등 제외 시 실제 타겟은 80~120만 명)

---

### ② XRPL 활용도: 7/10 ⚠️ 보완 필요

**좋은 점:**
- `Escrow`: 보증금 예치 → 계약 종료 시 자동 반환. XRPL 네이티브 기능의 **교과서적 활용**
- `DID`: 비자+고용보험 온체인 연동

**감점 이유 (-3):**

| 문제 | 상세 |
|------|------|
| "스마트 컨트랙트로 검증" 표현 | XRPL에는 이더리움 방식 스마트 컨트랙트가 **없음**. `Hook`이 있지만 아직 Mainnet 미배포. 심사위원 중 XRPL 전문가가 이걸 지적하면 치명적 |
| 활용 기능 다양성 부족 | SBT+는 5가지(Credential, DepositPreauth, DIDSet, Merkle Root, CredentialCreate), HI-DORRI는 4가지. 노목돈은 Escrow+DID 2가지 중심 |
| Cross-Currency Payment 미활용 | 해외 투자자가 참여할 수 있다면 XRPL의 **존재 이유**인 크로스보더 결제를 안 쓸 이유가 없음 |
| PaymentChannel 미활용 | 월세 분할 납부에 최적인 기능인데 언급 없음 |

> [!WARNING]
> **"스마트 컨트랙트" 표현을 반드시 수정하세요.** → `XRPL Escrow의 조건부 해제(Condition/Fulfillment)` 또는 `Hook 기반 자동 검증`으로 변경

---

### ③ 실현 가능성: 5/10 🔴 최대 약점

이게 노목돈의 **아킬레스건**입니다.

| 리스크 | 심각도 | 설명 |
|--------|--------|------|
| **3면 마켓플레이스** | 🔴 | 임차인 + 투자자 + 임대인 세 그룹을 **동시에** 모아야 함. 치킨앤에그 문제. 스타트업 역사상 가장 어려운 모델 |
| **금융 규제** | 🔴 | "보증금 반환채권 유동화" = 사실상 **자본시장법상 증권**. 금융투자업 인가 필요. P2P 대출 규제도 적용 가능 |
| **투자자 리스크** | 🟡 | 외국인 임차인이 비자 만료로 갑자기 출국하면? 보증금 반환 받을 수 있지만, 체불/야반도주 시 누가 손실 부담? |
| **임대인 참여 동기** | 🟡 | 임대인 입장에서 기존 방식(한국인 세입자에게 직접 보증금 수령)이 더 간편. 왜 굳이 프로토콜을 거쳐야 하는가? |
| **추가 월세 수준** | 🟡 | 시중 금리보다 높은 수익을 투자자에게 줘야 하는데, 그러면 외국인이 내는 추가 월세가 높아짐. 금리 경쟁력? |

**CredBundle과 비교하면:**
- CredBundle: 정부 API 연동 → 기존 데이터 활용 → 규제 허들 낮음
- 노목돈: 새로운 금융 상품 창출 → 규제 허들 **매우 높음**

> [!CAUTION]
> 심사위원이 "이거 대부업/P2P 라이선스 없이 가능해요?" 물으면 명확한 답이 있어야 합니다.

---

### ④ 확장성/임팩트: 8/10 ✅ 강점

**좋은 점:**
- 성공하면 임팩트 거대: 주거 안정 → 비자 연장 → 장기 정착 → 경제 기여의 선순환
- 보증금 → 전세 → 매매까지 부동산 금융 전반 확장 가능
- 축적되는 월세 납부 데이터 = 대한민국 유일의 외국인 주거 신용 데이터

**감점 이유 (-2):**
- 3면 마켓플레이스라 초기 스케일링이 극도로 느림
- 한국 부동산 시장 특수성이라 해외 확장 어려움 (다른 나라엔 전세가 없음)

---

### ⑤ 토스 시너지: 9/10 ✅ 강점

**좋은 점:**
- "토스 앱 내 외국인 전용 주거 섹션" — App in Toss 시나리오 매우 구체적
- 토스 부동산 탭이 이미 존재 → 확장 자연스러움
- 월세 결제 → 토스 recurring revenue
- 월세 납부 이력 축적 → 토스뱅크 신용평가 데이터 독점

**감점 이유 (-1):**
- CredBundle처럼 "토스뱅크 대출"을 직접 언급했지만, 노목돈의 핵심 가치 제안은 대출이 아니라 "보증금 유동화"라서 토스뱅크 기존 상품과의 연결이 CredBundle보다 한 단계 간접적

## 경쟁자 직접 비교

### vs CredBundle (1위, 45점) — 7점 차

| 비교 항목 | 노목돈 | CredBundle | 판정 |
|-----------|--------|-----------|------|
| 문제 구체성 | 보증금이라는 하나의 pain point | 금융 접근 전반 | 노목돈 승 |
| 감정적 호소력 | "목돈 없이 집 구하기" | "대출 심사 통과" | 노목돈 승 |
| 실현 난이도 | 3면 마켓 + 금융상품 규제 | 정부 API 연동 | **CredBundle 압승** |
| XRPL 필요성 | Escrow 필수 (DB로 대체 어려움) | Credential (DB로도 가능할 수 있음) | 노목돈 승 |
| 토스 적합성 | 외국인 주거 섹션 | 외국인 대출 심사 | 비김 |

> **핵심 차이**: 노목돈은 아이디어 참신성은 CredBundle보다 위. 하지만 **"3개월 안에 데모 가능한가?"**에서 CredBundle이 압도적으로 유리.

### vs Xfer (2위, 40점) — 2점 차

| 비교 항목 | 노목돈 | Xfer | 판정 |

| 실현 난이도 | 3면 마켓 | 송금업 라이선스 | 비김 (둘 다 어려움) |

|-----------|--------|------|------|

## 📊 점수를 올리려면?

### 실현 가능성 5→7 (가장 시급)

1. **규제 우회 구조 설계**
   - "보증금 유동화"를 P2P 대출이 아닌 **"전세보증보험 확장"** 프레임으로 포장
   - HUG(주택도시보증공사) 외국인 보증 상품 부재 → 노목돈이 민간 대안 제공
   
2. **3면 → 2면으로 단순화**
   - 초기엔 임대인을 제거: 토스가 제휴 부동산 중개업소와 직접 계약 → 투자자+임차인 2면만 관리
   - 또는 토스 자체가 초기 투자자 역할 (PoC 단계)

3. **리스크 관리 명시**
   - 임차인 디폴트 시: XRPL Escrow 조건부 해제 + 보증보험 적용
   - 비자 만료 시: Credential 만료 → 자동 정산 트리거

### XRPL 활용도 7→9

| 추가할 기능 | 용도 |
|------------|------|
| `PaymentChannel` | 월세 소액 반복 납부 (수수료 최소화) |
| `Cross-Currency Payment` | 해외 투자자 참여 (달러→원화 자동 환전) |
| `Credential` | 비자 상태 온체인 인증서 (DID 보완) |
| `DepositPreauth` | 투자자 등급별 참여 제한 |

### "스마트 컨트랙트" 표현 수정

```diff
- 임대차 계약 종료 및 명도 확인이 스마트 컨트랙트로 검증될 때만
+ 임대차 계약 종료 및 명도 확인이 XRPL Escrow의 조건부 해제(Crypto-Condition)로 검증될 때만
```

| **아이디어 참신성** | 🟢 **20팀 중 최상위**. 보증금 유동화를 XRPL로 푸는 팀 없음 |

| **실현 가능성** | 🔴 **최대 리스크**. 3면 마켓 + 규제. 이걸 해결 못 하면 "좋은 아이디어지만 현실성 부족"으로 탈락 |
| **프로토타입** | 🔴 SBT+, GG Banking 등은 이미 라이브. 데모 없으면 불리 |

> [!IMPORTANT]
> ### 한줄 요약
> **아이디어는 1등급, 실현 가능성이 발목을 잡아서 4위.**
> 
> 실현 가능성 답변을 준비하면 **CredBundle과 1:1 승부 가능**합니다.

> XRP팀 심사위원에게는 CredBundle보다 높은 점수를 받을 가능성도 있습니다.
